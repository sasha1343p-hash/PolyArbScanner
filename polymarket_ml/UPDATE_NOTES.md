#### 2. **Борьба с дисбалансом классов в `model.py`**

Добавлен `scale_pos_weight` для XGBoost и LightGBM:

```python
# Автоматический расчет веса для миноритарного класса
scale_pos_weight = (y == 0).sum() / max((y == 1).sum(), 1)
```

**Что это дает:**
- Если YES: 30%, NO: 70% → `scale_pos_weight = 2.33`
- Модель уделяет больше внимания миноритарному классу (YES)
- Улучшает recall для миноритарного класса
- Балансирует precision/recall

**Применяется:**
- В кросс-валидации (для каждого фолда отдельно)
- В финальном обучении на всех данных

#### 3. **Улучшенная калибровка в `calibrate_model.py`**

Изменен метод калибровки:

**Было:** `method='isotonic'`
- Требует много данных (1000+)
- Может переобучиться на малых выборках

**Стало:** `method='sigmoid'` (Platt scaling)
- Лучше работает на малых данных (200-500)
- Более стабильная калибровка
- Меньше риск переобучения

**Дополнительно:**
- Уменьшено количество фолдов: `cv=3` (вместо 5)
- Лучше для малых датасетов

### 📈 Новые фичи в деталях

#### `days_to_expiry` (Время до экспирации)

**Почему это важно:**
- Рынки с близкой экспирацией имеют более определенные исходы
- Модель учится: "если осталось 2 дня и цена 0.85, то YES очень вероятен"
- Критически для предсказания краткосрочных рынков

**Как вычисляется:**
```python
days_to_expiry = (end_date - now).days
```

**Диапазон:** 0-365 дней

---

#### `market_type_*` (Тип рынка)

**Почему это важно:**
- Крипто-рынки более волатильны
- Политические рынки имеют другие паттерны
- Спортивные рынки зависят от событий

**Как определяется:**
```python
# Крипто
if 'btc' in question or 'bitcoin' in question or 'eth' in question:
    return 'crypto'

# Политика
if 'trump' in question or 'election' in question:
    return 'politics'

# Спорт
if 'nba' in question or 'nfl' in question:
    return 'sports'
```

---

#### `volatility` и `volatility_ratio`

**Почему это важно:**
- Высокая волатильность = высокая неопределенность
- Модель учится: "если волатильность высокая, то предсказание менее надежно"

**Как вычисляется:**
```python
volatility = std(diff(prices))
volatility_ratio = std(prices) / mean(prices)
```

---

#### `trend` и `trend_strength`

**Почему это важно:**
- Показывает направление движения цены
- Модель учится: "если тренд положительный и сильный, то цена продолжит расти"

**Как вычисляется:**
```python
trend = polyfit(range(len(prices)), prices, 1)[0]
trend_strength = abs(trend)
```

### 🎓 Теоретическое обоснование

#### Почему эти фичи работают?

1. **Время до экспирации** - ключевой фактор неопределенности
   - Чем ближе экспирация, тем меньше неопределенности
   - Модель может учиться временным паттернам

2. **Тип рынка** - разные рынки имеют разные паттерны
   - Крипто: высокая волатильность, быстрые изменения
   - Политика: медленные изменения, зависимость от новостей
   - Спорт: бинарные исходы, зависимость от событий

3. **Волатильность** - мера неопределенности
   - Высокая волатильность = сложно предсказать
   - Модель может калибровать уверенность

4. **Тренд** - инерция цены
   - Цены имеют тенденцию продолжать движение
   - Модель может предсказывать направление

#### Почему scale_pos_weight важен?

- Реальные данные часто несбалансированы (например, 70% NO, 30% YES)
- Без scale_pos_weight модель игнорирует миноритарный класс
- С scale_pos_weight модель уделяет больше внимания редким случаям
- Улучшает recall для миноритарного класса

#### Почему sigmoid лучше isotonic?

- **Isotonic regression**: непараметрический метод, требует много данных
  - Хорошо работает на 1000+ примерах
  - Может переобучиться на малых выборках
  
- **Sigmoid (Platt scaling)**: параметрический метод (логистическая регрессия)
  - Хорошо работает на 200-500 примерах
  - Более стабильная калибровка
  - Меньше риск переобучения

### 🐛 Известные ограничения

1. **Новые фичи требуют переобучения**
   - Старая модель несовместима с новыми фичами
   - Нужно удалить старую модель и переобучить

2. **Классификация типа рынка может быть неточной**
   - Использует простые ключевые слова
   - Может ошибаться на сложных вопросах
   - В будущем можно использовать NLP

3. **scale_pos_weight не решает все проблемы дисбаланса**
   - Если дисбаланс слишком сильный (90/10), нужны дополнительные методы
   - Можно использовать SMOTE или undersampling
