# 🎯 Price Prediction Pipeline - Полное руководство

## 📋 Обзор

Система предсказания движения цен на предиктивных рынках Polymarket.

**Задача:** Предсказать, вырастет ли цена YES акции на X% в ближайшие Y часов.

## 📊 Детальное описание шагов

### Шаг 1: Генерация целевой переменной

**Файл:** `src/target_generator.py`

**Что делает:**
- Загружает часовые цены из БД
- Для каждой точки времени t:
  - Берет цену в момент t
  - Смотрит цену в момент t + horizon_hours
  - Если цена выросла на ≥ threshold → target = 1
  - Иначе → target = 0

**Параметры:**
- `price_increase_threshold` - порог роста (по умолчанию 5%)
- `horizon_hours` - горизонт предсказания (по умолчанию 24 часа)
- `min_data_points` - минимум часов данных для рынка (по умолчанию 48)

**Пример запуска:**
```bash
python run_target_generation.py --threshold 0.05 --horizon 24
```

**Результат:** `data/targets.csv`

---

### Шаг 2: Извлечение фич

**Файл:** `src/feature_extractor.py`

**Что делает:**
- Для каждой точки времени извлекает 50+ признаков:
  - **Momentum** - изменение цены за 1h, 6h, 12h, 24h, 48h, 168h
  - **Volatility** - стандартное отклонение returns за разные окна
  - **Trend** - наклон линейной регрессии за разные окна
  - **SMA** - скользящие средние (6h, 12h, 24h, 48h)
  - **RSI** - индекс относительной силы (14h, 24h)
  - **Volume** - средние объемы и их соотношение
  - **Distance** - расстояние от экстремумов (24h, 168h)
  - **Time** - час дня, день недели

**Пример запуска:**
```bash
python src/feature_extractor.py
```

**Результат:** `data/features.csv`

---

### Шаг 3: Подготовка датасета

**Файл:** `src/prepare_dataset.py`

**Что делает:**
- Объединяет фичи и targets по market_id и timestamp
- Удаляет пропуски
- Сохраняет объединенный датасет

**Пример запуска:**
```bash
python src/prepare_dataset.py
```

**Результат:** `data/dataset.csv`

---

### Шаг 4: Обучение модели

**Файл:** `src/model.py`

**Что делает:**
- Загружает датасет
- Разделяет фичи и target
- Обучает XGBoost с кросс-валидацией (TimeSeriesSplit)
- Сохраняет модель и список фич

**Параметры модели:**
- `n_estimators` = 200
- `max_depth` = 6
- `learning_rate` = 0.05
- `subsample` = 0.8
- `colsample_bytree` = 0.8
- `scale_pos_weight` = auto (балансировка классов)

**Пример запуска:**
```bash
python src/model.py
```

**Результат:** `models/price_movement_model.pkl`

---

### Шаг 5: Бэктестинг

**Файл:** `src/backtester.py`

**Что делает:**
- Загружает обученную модель
- Для каждой точки времени:
  - Предсказывает вероятность роста
  - Если P(рост) > threshold → покупка
  - Рассчитывает P&L на основе реального изменения цены
- Считает статистику:
  - Total P&L
  - Win rate
  - Max drawdown
  - Sharpe ratio

**Параметры:**
- `probability_threshold` = 0.65 (порог для покупки)
- `initial_capital` = 1000 (начальный капитал)
- `position_size` = 50 (размер позиции)

**Пример запуска:**
```bash
python src/backtester.py
```

**Результат:** `data/backtest_trades.csv`

## 📈 Интерпретация результатов

### Метрики модели

**Accuracy:** 60-70%
- Модель правильно предсказывает 60-70% случаев
- Лучше случайного угадывания (50%)

**Precision:** 55-65%
- Из всех предсказаний "рост будет" 55-65% правильные
- Показывает надежность сигналов

**Recall:** 50-60%
- Модель находит 50-60% всех реальных случаев роста
- Показывает полноту охвата

**AUC-ROC:** 0.60-0.70
- Качество классификации
- 0.5 = случайное угадывание
- 1.0 = идеальная классификация

### Результаты бэктестинга

**Total P&L:**
- Прибыль/убыток стратегии
- Положительное значение = прибыль

**Win rate:**
- Процент прибыльных сделок
- 50-60% = хорошая стратегия

**Max drawdown:**
- Максимальная просадка капитала
- Чем меньше, тем лучше
- -10% = приемлемо
- -20% = рискованно

**Sharpe ratio:**
- Отношение доходности к риску
- > 1.0 = хорошая стратегия
- > 2.0 = отличная стратегия

## 🔧 Устранение неполадок

### Ошибка: "База данных не найдена"

**Решение:**
```bash
cd ../polymarket_ml
python create_test_db.py
```

### Ошибка: "Нет данных для генерации targets"

**Причина:** Недостаточно часовых данных в БД

**Решение:**
- Уменьшите `min_data_points` в конфиге
- Добавьте больше данных в БД

### Ошибка: "Модель не обучена"

**Решение:**
```bash
python src/model.py
```

### Низкое качество модели (Accuracy < 60%)

**Причины:**
- Недостаточно данных
- Слишком высокий/низкий порог
- Нестабильные рынки

**Решения:**
- Увеличьте количество данных
- Настройте параметры `threshold` и `horizon`
- Попробуйте другие окна фич в `feature_extractor.py`

### Бэктестинг показывает убыток

**Причины:**
- Модель недостаточно точна
- Слишком низкий порог вероятности
- Высокие комиссии/проскальзывание

**Решения:**
- Увеличьте `probability_threshold` (например, 0.70)
- Уменьшите `position_size`
- Добавьте комиссии в бэктестер

## 🎓 Теоретическое обоснование

### Почему предсказание движения лучше бинарной классификации?

1. **Больше данных:**
   - Бинарная классификация: 200 рынков = 200 примеров
   - Предсказание движения: 200 рынков × 1000 часов = 200,000 примеров

2. **Фичи из временных рядов:**
   - Momentum, volatility, trend работают только с часовыми данными
   - Бинарная классификация не может их использовать

3. **Интерпретируемость:**
   - "Цена вырастет на 5% за 24 часа" понятнее
   - "YES с вероятностью 65%" менее конкретно

4. **Backtesting:**
   - Можно протестировать стратегию на истории
   - Оценить реальную прибыльность

### Почему XGBoost?

1. **Работает с табличными данными**
2. **Устойчив к переобучению**
3. **Быстрое обучение**
4. **Хорошая интерпретируемость (feature importance)**
5. **Поддержка class imbalance (scale_pos_weight)**

### Почему TimeSeriesSplit?

- Обычная кросс-валидация перемешивает данные
- Для временных рядов это приводит к data leakage
- TimeSeriesSplit сохраняет временной порядок
- Обучение на прошлом, тестирование на будущем
